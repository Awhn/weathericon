# 제품 요구사항과 MVP 범위

## 1. 문제와 목표

사용자는 외출 직전에 기온, 강수, 자외선, 미세먼지 수치를 각각 해석하고 싶지 않다. Weather Icon은 도시별 현재 상태를 조회해 **무엇을 입고 무엇을 챙길지**를 계기판 형태의 아이콘으로 즉시 설명한다.

MVP의 성공 기준은 다음과 같다.

- 국가·지역·좌표를 포함한 공유 가능한 도시 URI만으로 결과에 진입할 수 있다.
- 정상 응답 후 핵심 권고와 그 이유를 한 화면에서 이해할 수 있다.
- 동일한 입력 데이터에는 항상 동일한 추천 결과가 나온다.
- 외부 API 장애나 오래된 데이터를 정상 데이터처럼 표시하지 않는다.

## 2. 핵심 사용자 흐름

1. 사용자가 루트에서 서울을 검색하거나 공유된 `/city/대한민국/서울특별시/서울/37.5665,126.978` URI에 접속한다.
2. 시스템이 입력을 정규화하고 도시 후보를 검색한다.
3. 후보가 하나면 자동 선택하고, 여러 개면 국가·행정구역과 함께 선택지를 표시한다.
4. 선택한 위치의 현재 날씨와 대기질을 조회한다.
5. 정규화된 수치에 추천 규칙을 적용한다.
6. 활성 아이콘, 한 줄 권고, 판정 근거, 데이터 기준 시각을 표시한다.

`city`가 비어 있거나 공백뿐이면 입력 화면을 표시한다. 검색 결과가 없으면 입력값을 유지한 채 다시 검색할 수 있게 한다. 네트워크 오류에는 재시도 동작을 제공한다.

## 3. MVP 범위

### 포함

- 도시명 검색과 동명이인 도시 선택
- 현재 기온과 체감 온도
- 현재 및 가까운 시간대의 강수 가능성/강수량
- 현재 자외선 지수
- PM2.5와 PM10 대기질
- 반팔, 겉옷, 두꺼운 외투, 우산, 자외선 대비, 마스크 아이콘
- 권고가 활성화된 이유와 관측/예보 시각
- 로딩, 빈 결과, 일부 데이터 누락, 공급자 오류 상태
- 한국어 UI 우선, 단위는 섭씨와 `µg/m³`

### 제외

- 사용자 계정, 즐겨찾기, 푸시 알림
- GPS 자동 위치 추적
- 장기 예보와 여행 일정 추천
- 개인 건강 상태를 반영한 의료 조언
- 네이티브 모바일 앱

## 4. 초기 추천 정책

아래 값은 구현을 시작하기 위한 **제품 기본값**이다. 출시 전 기상·보건 기준 담당자의 검토와 사용자 테스트를 거치며, 코드의 상수가 아닌 버전이 있는 정책 모듈로 관리한다.

| 신호 | 초기 조건 | 표시할 권고 |
| --- | --- | --- |
| 체감 온도 | `>= 25°C` | 반팔 등 가벼운 옷 |
| 체감 온도 | `12–24.9°C` | 얇은 겉옷/겹쳐 입기 |
| 체감 온도 | `< 12°C` | 따뜻한 외투 |
| 강수 | 현재 강수량 `> 0` 또는 향후 3시간 최대 강수확률 `>= 40%` | 우산 |
| UV 지수 | `>= 3` | 모자·선글라스·자외선 차단 |
| PM2.5 | `> 35 µg/m³` | 마스크 고려 및 공식 지침 확인 |
| PM10 | `> 80 µg/m³` | 마스크 고려 및 공식 지침 확인 |

규칙 적용 원칙:

- 복장 판정에는 실제 기온보다 체감 온도를 우선한다.
- PM2.5 또는 PM10 중 하나만 기준을 넘어도 마스크 아이콘을 활성화한다.
- 데이터가 없으면 안전한 쪽으로 추측하지 않고 `판정 불가`를 명시한다.
- 서로 배타적인 복장 아이콘은 한 개만, 준비물 아이콘은 여러 개를 동시에 표시할 수 있다.
- 각 결과는 `ruleId`, 사용한 값, 임계값, 사람이 읽을 수 있는 이유를 반환한다.

## 5. 기능 요구사항

### URL과 입력

- 표준 경로는 `/city/{국가}/{지역}/{도시}/{위도,경도}`이다.
- 각 경로 조각은 URL 디코딩하고 검색 입력은 앞뒤 공백 제거 및 연속 공백 축약을 적용한다.
- 빈 값과 100자를 초과하는 값은 API 요청 전에 거부한다.
- 선택된 위치는 공급자의 일시적 ID가 아니라 위도·경도·표시 이름으로 상태에 보관한다.

### 결과 표현

- 색만으로 상태를 전달하지 않고 아이콘, 텍스트 레이블, 이유를 함께 쓴다.
- 위치는 `도시, 행정구역, 국가` 형태로 표시한다.
- 날씨와 대기질의 기준 시각 및 시간대를 표시한다.
- 일부 데이터만 실패하면 사용 가능한 결과를 보여 주되 누락 항목을 분명히 표시한다.

### 비기능 요구사항

- 모바일 360px 너비부터 사용할 수 있어야 한다.
- 키보드만으로 도시 후보 선택과 재시도가 가능해야 한다.
- 아이콘에는 접근 가능한 이름이 있어야 하고 장식 요소는 스크린 리더에서 숨긴다.
- 클라이언트 서비스 계층은 입력 검증, 요청 시간 제한, 공급자 오류 매핑을 제공한다.
- MVP가 사용하는 외부 API는 브라우저 호출(CORS)을 허용하고 공개 클라이언트에서 비밀 키를 요구하지 않아야 한다.
- API 키나 비밀 값은 환경 변수 형식이더라도 정적 번들에 포함하지 않는다. 비밀 값이 필요한 순간 BFF를 도입한다.

## 6. 수용 기준

- 고유 도시 URI를 읽으면 추가 도시 선택 없이 좌표 기반 날씨 조회가 시작된다.
- 동명 도시 응답에서는 사용자의 선택 전까지 날씨를 임의 조회하지 않는다.
- 경계값 바로 아래, 같은 값, 바로 위에 대한 추천 엔진 테스트가 존재한다.
- 날씨만 성공하고 대기질이 실패한 경우 복장·우산 결과와 대기질 오류가 함께 표시된다.
- 관측 시각과 현재 시각의 차이가 허용 범위를 넘으면 오래된 데이터 경고를 표시한다.
- 공급자 고유 필드명은 React 컴포넌트 또는 추천 규칙에 노출되지 않는다.

## 7. 추후 결정할 항목

- 3시간 강수 판단을 최대값과 누적값 중 무엇으로 보정할지
- 계절, 습도, 풍속을 복장 정책에 반영할지
- 지역별 대기질 기준을 자동 선택할지
- 캐시 TTL과 `오래된 데이터`의 정확한 허용 시간
- 공급자 이용량 증가 시 유료 플랜 또는 대체 공급자 전환 기준
